# s03 TodoWrite 学习总结

## 本章主题

第三章学习的是 TodoWrite，也就是给 Agent 增加一个可见、可更新、可约束的任务清单。

前两章已经让 Agent 具备了基础行动能力：

```text
s01：Agent Loop，让模型能通过工具循环行动
s02：Tool Use，让模型能调用多个专用工具
```

但是有了工具之后，Agent 仍然会遇到一个问题：

```text
多步任务中，模型容易忘记进度、重复操作、跳步或跑偏。
```

所以 s03 增加了 `todo` 工具，让模型自己维护任务清单。

本章核心格言是：

```text
没有计划的 agent 走哪算哪。
```

---

## 一、为什么有了工具之后还需要 TodoWrite

工具解决的是：

```text
Agent 能做什么。
```

例如：

```text
read_file：读文件
write_file：写文件
edit_file：改文件
bash：执行命令
```

但工具不解决：

```text
Agent 如何持续完成一个多步任务。
```

例如用户要求：

```text
重构 hello.py：添加类型注解、添加 docstring、添加 main guard、运行测试
```

如果没有 TodoWrite，Agent 可能会：

- 读完文件后忘记运行测试；
- 改了一半就开始总结；
- 重复做已经完成的事情；
- 漏掉某个步骤；
- 不知道当前正在做哪一步。

因此，TodoWrite 的作用是：

```text
给 Agent 一个可见的任务清单，让它持续追踪“已完成、正在做、待完成”。
```

工具让 Agent 有行动能力，TodoWrite 让 Agent 有进度管理能力。

---

## 二、TodoWrite 是控制模型，还是辅助模型

TodoWrite 是辅助模型，不是完全控制模型。

它不会像传统工作流一样强制规定：

```text
必须先做 A，再做 B，再做 C。
```

它只是提供一个工具，让模型自己写计划、更新状态、追踪进度。

模型仍然决定：

- 任务怎么拆；
- 先做哪一步；
- 什么时候更新状态；
- 什么时候标记完成；
- 是否调整计划。

Harness 负责：

- 提供 `todo` 工具；
- 保存 todo 状态；
- 校验 todo 格式；
- 限制同时只能有一个 `in_progress`；
- 必要时注入 reminder。

所以 TodoWrite 更准确的理解是：

```text
Harness 给模型提供一个规划空间，而不是替模型规划路线。
```

---

## 三、TodoManager 中每个任务有哪些状态

TodoManager 中每个任务通常有三个状态：

```text
pending：还没开始做
in_progress：正在做
completed：已经完成
```

显示时通常对应：

```text
[ ] pending
[>] in_progress
[x] completed
```

例如：

```text
[x] #1: 阅读 hello.py
[>] #2: 添加类型注解
[ ] #3: 运行测试
```

这表示：

```text
第 1 步已经完成
第 2 步正在进行
第 3 步还没开始
```

TodoManager 的价值在于把模型的隐式计划变成显式状态。

---

## 四、为什么同一时间只允许一个 in_progress

s03 中有一个重要约束：

```text
同一时间只允许一个任务处于 in_progress 状态。
```

原因是为了强制 Agent 保持当前焦点。

如果允许多个任务同时是 `in_progress`，任务清单可能变成：

```text
[>] #1: 阅读文件
[>] #2: 修改代码
[>] #3: 运行测试
```

这看起来像是在同时做很多事，但实际上会让当前目标变得模糊。

更好的状态是：

```text
[x] #1: 阅读文件
[>] #2: 修改代码
[ ] #3: 运行测试
```

这样模型可以清楚知道：

- 已经完成什么；
- 当前正在做什么；
- 下一步要做什么。

所以“同一时间只允许一个 in_progress”的作用是：

- 防止任务焦点混乱；
- 防止模型假装并行；
- 让执行顺序更清晰；
- 让人类更容易观察进度。

## 五、nag reminder 解决什么问题

`nag reminder` 解决的是：

```text
Agent 连续调用其他工具，却忘记更新 todo。
```

例如模型连续几轮都在调用：

```text
read_file
edit_file
bash
```

但一直没有调用：

```text
todo
```

这时 Harness 会注入提醒：

```text
<reminder>Update your todos.</reminder>
```

这个 reminder 不是基于真实时间的定时机制，而是基于 Agent Loop 的轮次计数机制。

它的逻辑是：

```text
每发生一轮工具调用，就检查这一轮有没有调用 todo。
如果没有调用，rounds_since_todo += 1。
如果调用了 todo，rounds_since_todo = 0。
如果连续 3 轮没有调用 todo，就注入 reminder。
```

也就是说，它不是：

```text
每 30 秒提醒一次。
```

而是：

```text
连续若干轮没有更新 todo，就在下一轮上下文里提醒模型。
```

它是一种软约束，不是强制控制。

作用是把偏离计划管理的 Agent 拉回任务追踪状态。

## 六、TodoWrite 和真正的任务系统有什么区别

TodoWrite 是轻量级的、单 Agent 内部的任务清单。

真正的任务系统是持久化、可协作、可恢复、可审计的系统。

| 对比项 | TodoWrite | 真正的任务系统 |
|---|---|---|
| 保存位置 | 通常在内存或当前上下文 | 文件、数据库、任务队列 |
| 使用对象 | 单个 Agent | 多个 Agent / 人类 / 系统 |
| 任务结构 | 简单 id、text、status | 任务依赖、负责人、输入输出、日志、成本 |
| 生命周期 | 当前会话内 | 可跨会话、可恢复 |
| 协作能力 | 弱 | 强 |
| 审计能力 | 弱 | 强 |
| 失败恢复 | 基本没有 | 可以重试、回滚、升级 |
| 适用场景 | 单次多步任务 | 企业级流程自动化 |

可以这样理解：

```text
TodoWrite 是任务系统的雏形。
```

后面的 s07 Task System 会把它升级为真正的持久化任务图。

## 七、企业流程 Agent 中，TodoWrite 可以如何升级

在企业流程 Agent 中，TodoWrite 可以升级成正式的任务管理系统。

例如企业文档审查流程可以从简单 todo：

```text
[ ] 解析文档
[ ] 抽取事实
[ ] 检查一致性
[ ] 生成报告
```

升级为结构化任务对象：

```json
{
  "id": "task_003",
  "title": "检查跨文档一致性",
  "status": "in_progress",
  "owner": "consistency_agent",
  "priority": "high",
  "input_docs": ["doc_a.pdf", "doc_b.docx"],
  "dependencies": ["task_001", "task_002"],
  "evidence": [],
  "errors": [],
  "created_at": "2026-05-15T21:00:00+09:00",
  "updated_at": "2026-05-15T21:20:00+09:00"
}
```

可以增加这些能力：

- 持久化：保存到数据库或文件，任务不会因会话结束丢失；
- 依赖管理：任务 B 必须等任务 A 完成后才能开始；
- 负责人分配：不同任务交给不同 Agent 或人工处理；
- 失败重试：工具失败后自动重试或升级；
- 人工复核：高风险任务转给人类审批；
- 审计日志：记录每一步输入、输出、证据和操作时间；
- 成本统计：记录每个任务消耗的 token、时间和 API 成本；
- 状态看板：让人类看到整个流程进度。

所以企业级升级路径是：

```text
TodoWrite
→ Task System
→ 多 Agent 协作任务图
→ 企业流程自动化平台
```

## 十、本章需要记住的问题答案

### 1. 为什么有了工具之后还需要 TodoWrite？

因为工具只解决 Agent 能做什么，不解决 Agent 如何持续完成多步任务。TodoWrite 让 Agent 能追踪已完成、正在做和待完成的任务。

### 2. TodoWrite 是控制模型，还是辅助模型？

TodoWrite 是辅助模型。它提供规划空间和状态记录，但具体怎么拆任务、怎么执行，仍由模型决定。

### 3. TodoManager 中每个任务有哪些状态？

有三种状态：`pending`、`in_progress`、`completed`，分别表示未开始、正在做、已完成。

### 4. 为什么同一时间只允许一个 in_progress？

为了强制当前焦点，避免模型同时声称做多个任务，导致目标混乱。

### 5. nag reminder 解决什么问题？

解决模型连续调用其他工具但忘记更新 todo 的问题。它基于轮次计数，不是基于时间定时。

### 6. TodoWrite 和真正的任务系统有什么区别？

TodoWrite 是轻量、单 Agent、当前会话内的任务清单；真正的任务系统是持久化、可协作、可恢复、可审计的企业级流程系统。

### 7. 企业流程 Agent 中，TodoWrite 可以如何升级？

可以升级为带持久化、依赖管理、负责人、失败重试、人工复核、审计日志和成本统计的任务系统。
