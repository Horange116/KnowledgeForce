# AI 产品与业务流程智能化方向

## 1. 方向定位

AI 产品与业务流程智能化方向是 Agent 工程路线的重要辅助方向。

核心目标是：

> 理解真实企业流程，判断哪些业务环节适合被 AI Agent 辅助或替代，并把 AI 技术能力设计成可落地、可评估、可迭代的产品方案。

这个方向不是当前主投方向，但它决定了能否把 Agent 用在真实业务中，而不是只做技术 Demo。

## 4. 核心能力

### 4.1 业务流程拆解

需要能回答：

- 这个岗位每天在做什么？
- 输入是什么？
- 输出是什么？
- 中间有哪些判断步骤？
- 哪些步骤重复、规则明确、信息密集？
- 哪些步骤需要专家判断？
- 哪些步骤必须保留人工确认？
- 哪些步骤可以交给 Agent？

### 4.2 Agent 产品设计

需要能设计：

- 用户入口
- 任务输入方式
- Agent 能力边界
- 工具链
- 知识库
- Workflow
- 人工确认节点
- 输出格式
- 失败兜底
- 权限控制
- 日志与反馈

### 4.3 PRD 与算法侧 PRD

普通 PRD 关注：

- 用户场景
- 功能需求
- 交互流程
- 验收标准
- 指标体系

算法侧 PRD 还要描述：

- 输入数据
- 输出格式
- 正负样例
- 评测集
- 模型指标
- 失败案例
- 人工标注规则
- 召回率 / 准确率 / 延迟 / 成本要求

### 4.4 指标体系

常见业务指标：

- 任务完成率
- 用户采纳率
- 人工修改率
- 平均处理时长
- 节省时间
- 用户满意度
- 转化率
- GMV
- ROI

常见 Agent 指标：

- 回答准确率
- 引用正确率
- 工具调用成功率
- 多步任务成功率
- 格式合法率
- 延迟
- 成本
- 鲁棒性
- 安全性

## 5. 和 Agent 应用工程的关系

| 维度 | AI 产品与业务流程智能化 | Agent 应用工程 |
|---|---|---|
| 关注点 | 发现问题、定义方案、设计指标 | 实现系统、接入工具、部署评测 |
| 主要产出 | PRD、流程图、指标体系、评测方案 | 代码、API、Agent Workflow、Demo |
| 核心能力 | 业务理解、产品设计、流程拆解 | RAG、Tool Calling、FastAPI、LangGraph |
| 价值 | 保证做的是有业务价值的 Agent | 保证 Agent 能真实运行 |

理想状态是两者结合：既能拆业务，又能动手实现。

## 6. 推荐方法：企业流程 Agent 化五步法

### 第一步：流程拆解

把业务流程拆成：

```text
输入 → 判断 → 检索 → 处理 → 决策 → 输出 → 反馈
```

### 第二步：任务分类

判断每个环节属于：

- 信息检索
- 内容生成
- 结构化抽取
- 规则判断
- 多文档对比
- 工具操作
- 人工审批
- 风险判断

### 第三步：Agent 能力映射

映射到：

- RAG
- Tool Calling
- Workflow
- Memory
- Structured Output
- Human-in-the-loop
- Eval

### 第四步：设计 MVP

先做最小可用版本：

- 一个核心场景
- 一个输入入口
- 三到五个工具
- 一个结构化输出
- 一套评测用例

### 第五步：指标闭环

建立：

- 使用日志
- 用户反馈
- 失败案例
- 评测集
- 指标看板
- 版本迭代记录

并沉淀作品集。

## 10. 当前阶段建议

这个方向应该作为 Agent 工程路线的辅助能力，而不是替代工程能力。

当前最佳策略：

1. 主项目仍然做企业文档审查 Agent。
2. 同时为这个项目补一份 PRD。
3. 补一份算法侧 PRD。
4. 补一张业务流程图。
5. 补一张 Agent Workflow 图。
6. 补一套指标体系。
7. 补一份评测集设计说明。

这样既能投 Agent 工程岗，也能体现业务流程智能化能力。

## 11. 投递建议

当前不建议主投纯 AI 产品经理岗。

更适合的组合定位是：

> 懂业务流程拆解的 AI Agent 应用工程师。

可以投递：

- AI Agent 应用工程师
- 大模型应用工程师
- RAG 工程师
- 企业智能体开发实习生
- 技术型 AI 产品实习生
- 大模型评测 / 数据产品实习生

不建议优先投递：

- 纯商业化产品经理
- 纯增长产品经理
- 纯营销 SaaS 产品经理
- 纯 AIGC 素材产品经理
